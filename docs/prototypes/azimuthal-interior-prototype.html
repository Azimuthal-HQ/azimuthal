The create-item dialog. The headline fix is the priority selector — rebuilt as a segmented control with equal-width options and a colour dot per level, replacing the four cramped chips. Modal over a dimmed board.

Why segmented, not a dropdown. Priority has four fixed values chosen constantly — a segmented control shows all of them at once, colour-codes them, and takes one click. A dropdown hides three options behind a click every time. The colour dots also match the priority pills used on the board and detail views, so the language is consistent end to end.

Ticket detail — two-column: content left, properties right. Replaces the current view, which stacks everything in one column with unstyled fields. The tab row (Detail / Activity / Comments) sits under the description.

DEVOPS-48
Login page returns 500 after password reset
In progress High Beacon

Users who reset their password can't log back in — the OAuth callback returns a 500. Started immediately after the last deploy.

Steps to reproduce

  • Request a password reset from the login page
  • Follow the email link and set a new password
  • Attempt to log in — the callback 500s with invalid_grant

Suspected cause

The token refresh change in auth/callback.go looks like the culprit — the reset flow issues a token the callback doesn't expect.

The priority control, before and after — isolated so the change is unmistakable.

Before
Four content-width chips, minimal padding, no colour coding.
Reads as loose chips. Hard to tell it's one control, and nothing signals severity.
After
Equal-width segments, a colour dot per level, one connected control.
Obviously one control. Severity is colour-coded, and the dots match the priority pills everywhere else.
Reuse beyond priority. The segmented control isn't priority-specific — it's the pattern for any small fixed set of exclusive choices. The user/team toggle on the grants panel uses the same component, so it's worth building once as a shared primitive rather than a one-off.
